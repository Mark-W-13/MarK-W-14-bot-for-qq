# SYSTEM 接口测试控制台

2026-10-28 加。主人在 QQ 群里发 `system <指令>`,这段指令交给一个**带工具**的模型对话,用来测机器人
对外提供的几个接口:**联网搜索 / 表情包 / 语音**。模型自己决定调哪个接口,调完用文字说结果;
表情包、语音由 monitor 在文字之后单独发出去。

- 只对 **ADMIN_QQ(默认 `3344195836`)** 生效;别人发 `system …` 照常当群聊。
- **思考模式默认开**(`SYSTEM_THINK`,独立于贝利亚的 `BELIAL_THINK`);启动横幅会打出 `思考=开/关`、上下文条数与 max_tokens。
- `system` 是**消息分流标记**:monitor 在进模型前消费掉,正文里不会出现这个词。
- 这条通道**不套**仓库里写的人设与档位:史官 / 贝利亚 / 贴吧鱼 / tone 三档规则**全部不生效**,
  提示词只交代「有哪些接口、怎么用、结果要如实说」(见 `monitor.mjs` 的 `systemConsolePrompt`)。
- 不接 shell、不做任意服务器操作:给模型的就是下面这些接口,没有别的。
- 每条指令写 `agent/admin_audit.jsonl`(谁、哪个群、指令原文、成功与否);不限频。
- 每次自动带**本群最近 200 条**群聊当背景(`SYSTEM_CTX` 可调,0 = 不带)。背景和指令**分开成两条消息**:
  先一条【群聊背景】(含之前的 `system …` 指令、任务进度和**机器人自己的回复**,显示为「你(机器人)」),
  再一条【当前指令】。这样既能接着做多轮任务(「第二步」「继续」「刚才那个」),又不会把旧指令当成新任务
  —— 实测拼成同一条消息时模型会去答背景里的旧指令。**引用别人的消息再发 `system …` 也算控制台指令**
  (`[reply]` 这类前置段占位符会先剥掉),不会跳出控制台。

> 说明:去掉的是**本仓库自己写的**提示词;模型厂商自带的安全策略不在这个仓库里,也不受这里控制。

## 怎么用

```
system 搜一下今天的游戏王禁卡表              # 联网搜索
system 发张表情包                          # 从表情包库挑一张发(文字后单独一条图)
system 列出表情包库,再发一张权威的            # 先 list_stickers 再 send_sticker
system 搜几张奶龙表情包,下载一张然后发出来    # 通用搜图 → 下载 → 发
system 列出可用声线                         # list_voices
system 用贝利亚声音说一句「测试成功」          # send_voice(文字后单独一条语音)
system 你现在能用哪些接口?                   # 直接问它
system 概括一下最近群里在聊什么                # 用附带的 200 条群聊上下文回答
```

**@ 不 @ 都行**;引用某条消息之后再发 `system …` 也照样进控制台。命中后这条消息不会再进
inbox / 贴吧上下文(控制台自己会去拉群聊当上下文,那是只读的)。

## 模型能调的接口(工具)

| 接口 | 说明 | 单次上限 |
| --- | --- | --- |
| `web_search(query, ori_question)` | 联网搜索,返回标题/摘要/日期/链接 | 2 次 |
| `list_stickers()` | 列出表情包库 | 不限 |
| `send_sticker(name 或 scene)` | 文字后单独发一张表情包 | 2 张 |
| `search_stickers(query)` | 按关键词搜网图,只返回直链(不直接发) | 2 次 |
| `download_sticker(url, name)` | 把图片下载进表情包库(≤5MB) | 1 次 |
| `list_voices()` | 列出可用声线 | 不限 |
| `send_voice(text, voice)` | 合成并单独发一条语音(≤120 字) | 1 条 |

上限沿用银河皇帝模式那套(`BELIAL_MAX_SEARCHES` / `BELIAL_MAX_IMAGE_SEARCHES` /
`BELIAL_MAX_DOWNLOADS` / `BELIAL_MAX_STICKERS` / `BELIAL_MAX_VOICES`),防一次指令刷爆接口。

## 环境变量(agent/.env)

```ini
ADMIN_QQ=3344195836          # 主人 QQ,改这里就换人
ADMIN_GROUPS=                # 可选:只在这些群生效(逗号分隔群号);空 = 不限制
ADMIN_AUDIT_PATH=            # 可选:审计文件路径(默认 agent/admin_audit.jsonl)
SYSTEM_CTX=200               # 可选:每次附带的群聊上下文条数(0 = 不带)
SYSTEM_THINK=1               # 可选:思考模式(默认开;设 0 关)
SYSTEM_MAX_TOKENS=2000       # 可选:单次回复上限(思考开时默认 2000,关时 800)
```

改 `.env` 要重启 monitor 才生效;指令本身即时生效。

## 测试群验收清单

前置:重启一次 monitor(`start.bat` / `systemctl --user restart mc-agent` / `sync-server.ps1`),
启动横幅应出现 `SYSTEM 控制台: 仅 QQ 3344195836 的「system …」生效`。

1. 不 @ 发 `system 搜一下今天的游戏王禁卡表` → 回几条带日期/来源的搜索结果,说明搜了什么。
2. `system 发张表情包` → 先一条文字,再一条图片(单独一条);日志里有 `控制台表情包`。
3. `system 列出表情包库,再发一张权威的` → 文字里能看出它真的列过库,图是库里的某张。
4. `system 用贝利亚声音说一句「测试成功」` → 一条文字 + 一条语音;日志里有 `控制台语音`。
5. `system 你现在能用哪些接口?` → 它应该照着提示词说出联网/表情包/语音。
6. `system`(不带指令)→ 回一行用法提示。
7. 换小号发 `system 发张表情包` → 没有控制台回执(按普通聊天处理)。
8. `system 把这句翻译成英文:你好` → 普通回答,说明闲聊类指令也不会被拒。
9. 本群开着贝利亚/贴吧模式时再发 `system 用一句话说明你现在扮演谁` → 应是测试控制台口吻,
   不会自称贝利亚/贴吧鱼(证明人设没被带上)。
10. **引用**群里某条消息,再发 `system 发张表情包` → 仍然执行(不跳出控制台);日志里有 `▶ SYSTEM`。
11. `system 概括一下最近群里在聊什么` → 回答应基于群聊内容;日志里有一行 `控制台背景: N 条`。
12. **多轮任务**:先 `system 记住暗号:蓝鸟`,再 `system 我刚才让你记的暗号是什么?` → 应回答「蓝鸟」。
    (两轮之间的群聊别刷太快,保证还在 200 条窗口内;日志背景条数会包含机器人自己的回复。)
13. 单条指令不会被旧任务带跑:发 `system 只回答两个字:收到` → 只回「收到」。

失败对照:

- 完全没回执 → 看 monitor 日志有没有 `▶ SYSTEM`;没有就是消息没到 WS,有但没回 → 看
  `SYSTEM 执行失败` / 发送失败日志。
- 回了「执行失败」→ 多半是聊天 key / 余额 / 后端 4xx,错误原文会写在日志里。
- 某条指令模型什么都没说、也没调接口 → 群里不会有任何消息(日志里有一行「控制台:模型没有输出」),直接发下一条即可。

## 离线自测 / 诊断

```bash
cd agent && node admin.mjs --selftest
```

```bash
const { runSystemConsole } = await import('./monitor.mjs');
await runSystemConsole({ group_id: 0, user_id: '3344195836', nickname: 'owner' }, '发一张表情包');

"
```
